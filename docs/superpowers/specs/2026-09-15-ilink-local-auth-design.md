# iLink 本地鉴权设计

## 目标

iLink Bot 的登录信息由本项目保存在 `~/.lkcoffee`，首次执行 `bun run bot` 自动完成二维码登录；已有本地凭据时直接启动，不再依赖或读取下载目录。

## 数据与运行流程

`~/.lkcoffee/account.json` 保存 iLink 的 `botToken`、bot 标识、服务端地址和保存时间，创建及更新时使用 0600 权限。`~/.lkcoffee/state.json` 保存长轮询游标，同样使用 0600 权限。

启动 Bot 时先读取账户文件；文件不存在则请求 iLink 二维码，在当前终端显示二维码并轮询其状态。扫码确认后写入账户文件，然后继续 `notifystart` 和长轮询。登录令牌、二维码内容和游标不写日志，也不提交到仓库。

## 最小改动

迁入演示项目已验证的二维码协议路径：二维码申请、状态查询、重定向主机、配对码和确认结果。增加 `qrcode-terminal`，不增加账号选择、登出命令、凭据迁移或外部目录兼容层。移除 `ILINK_DATA_DIR` 和 `/Users/passer/Downloads` 默认路径。

## 验证

单元测试验证账户保存在 `~/.lkcoffee` 形式的数据目录、文件权限为 0600，且已有账户被加载时不会调用登录流程。执行 `bun test`、`bun run typecheck`；在没有本地账户时实际运行一次扫码登录，在已有账户时再次启动并确认未展示二维码。
